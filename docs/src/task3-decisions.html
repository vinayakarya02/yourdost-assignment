AI-powered wellbeing navigator

Wellbeing Compass. Not sure where to start? Let’s find your next step together.

A gentle, three-minute check-in that helps an employee or student work out what kind of support might help, and then guides them to one appropriate next step inside YourDOST. It is not a therapist, a diagnosis or a crisis service.

1Problem identified

YourDOST already offers counselling, self-help, assessments and programmes, but users must self-diagnose which door to open. People who feel ‘off’ but can’t name it either bounce, or default to the highest-commitment option (a therapist) or the lowest (an article). Neither reliably helps, and both waste corporate benefit spend.

2Target user

First-time and low-engagement users in corporate and campus programmes: people who are stressed, sleeping badly or feeling low, who haven’t used counselling before and won’t fill in a long form.

3Why AI is useful here

  • People describe problems in their own words (“I lie awake replaying work”); an LLM can map that to the right support category better than fixed menus.
  • It can write a warm, specific summary and explanation, which builds trust that the suggestion fits.
  • It must never choose outside the catalogue, diagnose or assess risk. Those stay deterministic.

4Proposed solution

A one-question-at-a-time check-in (5 required, 1 optional free text) → a results page with one primary next step, transparent ‘why this may help’ reasons, and three support options (a matched therapist, self-help, a programme). Continuity features (save, keep this counsellor, post-session feedback) let users come back without pressure.

The safety screen runs on every free-text keystroke and again on the server. Crisis language replaces the journey with human support.

6Key features

  • Immersive check-in: progress, back/skip, validation, privacy notes
  • Personalised results: summary, primary step, reasons, uncertainty note
  • Therapist discovery: search, 6 filters, explainable match score, drawer profile, demo booking with slot validation and confirmation
  • Resource library: 7 topics, 5 formats, working guided activities, video preview, non-diagnostic reflections, programme enrolment
  • My Space: saved items, demo sessions, 3-question post-session feedback, ‘keep this counsellor’
  • Always-visible ‘Need help now?’ sheet

7AI architecture

The LLM receives the structured answers, the note (as untrusted user text), the rule baseline and an allow-list of resource IDs. It returns a JSON schema: summary, support needs, next-step type, title, description, reasons, professional-support flag, resource IDs, uncertainty, safety level. The server rejects anything off-schema, any ID outside the catalogue, and any copy containing diagnostic language, and then serves the rule result instead. Therapist and programme choice stay deterministic (the Task 2 matching engine). The API key lives only in a server environment variable.

8Rule-based fallback

The app is fully functional without an API key. A deterministic engine (lib/engine.ts) maps the answers to a next step:

SignalNext step
Prefers talking to a professionalCounselling
High impact + struggling (not ‘independent’)Counselling, gently framed
Guided preference / sleep concernProgramme or guided exercise
Independent, high impactSelf-reflection + ‘talking may help’ note
Independent, light impactCurated resources

An internal ‘support signal’ (impact + state + duration) is never shown and is not a severity score. It only decides whether professional support is mentioned as ‘worth considering’. If the API is down or slow, the server, and then the browser itself, fall back to the same engine, and the results page labels the mode used.

9Assumptions & trade-offs

  • One primary step, not a menu: less choice overload, at the risk of a wrong first guess. Mitigated by two alternatives and ‘edit answers’.
  • LLM writes, rules decide: a little less ‘magic’ for far more predictability, safety and testability.
  • Regex safety screen: transparent and instant but imperfect. It errs toward showing help; it is a routing aid, not risk detection.
  • No accounts in the prototype: state lives in the browser, which is enough to demonstrate continuity without collecting identity.
  • 3D hero: lazy-loaded, with a CSS fallback for no-WebGL, low-memory devices and reduced motion.

10Safety & privacy decisions

  • Deterministic crisis screen before any AI, on client and server; urgent language stops recommendations and shows 112 and Tele-MANAS 14416 plus a human-support request.
  • Ordinary sadness, stress or anxiety is not treated as an emergency (unit-tested, including “this deadline is killing me”).
  • The AI can raise the safety level but never lower it below the rules.
  • No diagnoses, labels or severity scores anywhere; reflections say “not a test”.
  • The free-text note is never stored. Only structured answers go to sessionStorage; saved items and demo bookings go to localStorage (verified in the browser). The server logs only error classes, never content.
  • No names, emails or phone numbers are collected. Security headers are set and the API key stays server-side.

12Future improvements

Validate

  • Clinician review of 50 scripted check-ins (AI vs rules)
  • Red-team the safety screen in Hindi, Hinglish and regional languages
  • Moderated usability tests with 8–10 first-time users

Build

  • Real catalogue and live therapist availability APIs
  • Authenticated continuity across devices; post-session feedback loop into matching weights
  • Multilingual check-in

Learn

  • A/B test ‘one step’ vs ‘three options’
  • Calibrate the Task 2 weights on outcome labels
  • Aggregated, anonymised insights for HR (k ≥ 10)
